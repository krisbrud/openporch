# openporch_driver (Resource)

An external HTTP driver's registration: where openporch reaches the driver, the bearer token it sends and what the driver supports. Resource definitions name it in `driver_type`. Changes update the registration in place, so rotating the token or moving the target keeps the definitions that use it; the server refuses a change while an operation the driver ran has an outcome that is not known yet, or one that stops the driver targeting the type of a definition using it. A `token` is written to the built-in secret store and kept in the OpenTofu state, so protect the state; see the provider documentation. A driver that definitions or active resources use cannot be deleted. Import it by ID; the token is imported as a reference. Needs a server with `PUT /orgs/{org}/resources/drivers/{driver}`.

## Example Usage

```terraform
# An external HTTP driver; the token is written to the built-in store. Changing
# the token or the target updates the registration in place.
resource "openporch_driver" "vault_db" {
  id     = "acme/vault-db"
  target = "https://drivers.acme.example/vault-db"
  token  = var.driver_token
  capabilities = {
    observe = true
  }
}

resource "openporch_resource_definition" "vault_db" {
  id          = "vault-db"
  type        = "postgres"
  driver_type = openporch_driver.vault_db.id
}
```

## Schema

### Required

- `id` (String) The driver ID, `<namespace>/<name>`; the `openporch` namespace is reserved. Changing it replaces the driver.
- `target` (String) The `https` URL the driver is reached at, without credentials, query or fragment. The server checks only that it is a valid `https` URL; deployments find out whether it can be reached.

### Optional

- `capabilities` (Attributes) What the driver supports beyond provisioning and removing resources. Left out, the driver provisions resources other than workloads and nothing more. The protocol has no preview call, so a driver never previews. (see [below for nested schema](#nestedatt--capabilities))
- `cookie_version` (Number) The cookie format version the driver writes. Left out, the server's default (`1`) is pinned when the driver is registered, and kept afterwards.
- `inputs_schema` (Dynamic) JSON Schema of the driver inputs, an object, recorded for clients.
- `outputs_schema` (Dynamic) JSON Schema of the driver's outputs, an object, recorded for clients.
- `protocol_version` (String) The protocol the driver speaks. Left out, the server's default (`openporch-http/1`) is pinned when the driver is registered, and kept afterwards.
- `token` (String, Sensitive) The bearer token sent to the driver, written to the built-in store. Changing it writes a new version. The server never returns it; `written_token_ref` records the version written, and a version changed outside OpenTofu plans a write of this token again. Conflicts with `token_ref`; with neither, the driver gets no token.
- `token_ref` (Attributes) The bearer token as a reference to a secret already in a store. Referencing a secret openporch did not write for this driver needs a secret-use grant, and of the driver's own secrets only the token it holds now may be referenced. (see [below for nested schema](#nestedatt--token_ref))

### Read-Only
