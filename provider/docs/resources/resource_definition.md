# openporch_resource_definition (Resource)

A resource definition: which driver provisions a resource type, with which inputs. It matches nothing until it has criteria, which are `openporch_resource_definition_criteria` resources. Placeholders such as `${context.app.id}` are written `$${context.app.id}` in HCL, so OpenTofu does not interpolate them. Secret values in `driver_secrets` are written to the built-in secret store and kept in the OpenTofu state, so protect the state; see the provider documentation. Import it by ID; secrets are imported as references.

## Example Usage

```terraform
# openporch placeholders are written $${...} so OpenTofu does not interpolate
# them.
resource "openporch_resource_definition" "redis" {
  id             = "redis"
  type           = "redis"
  driver_type    = "openporch/opentofu"
  driver_account = openporch_cloud_account.aws.id
  driver_inputs = {
    source    = { url = "https://github.com/acme/modules", path = "redis" }
    variables = { name = "$${context.app.id}-$${context.env.id}" }
  }
  driver_secrets = {
    variables = {
      # Written to the built-in store.
      auth_token = var.redis_auth_token
      # Kept as a template and resolved at deployment.
      upstream_password = "$${resources.postgres.outputs.password}"
    }
  }
}
```

## Schema

### Required

- `driver_type` (String) The driver, such as `openporch/opentofu`.
- `id` (String) The definition ID. Changing it replaces the definition.
- `type` (String) The resource type it provisions, such as `postgres`. Changing it replaces the definition.

### Optional

- `driver_account` (String) The cloud account the driver uses, or a `$${resources....account}` placeholder.
- `driver_inputs` (Dynamic) The driver's plain inputs, an object such as `{ script = "…", variables = { … } }`.
- `driver_secret_refs` (Dynamic) Secret inputs as references to secrets already in a store, nested like `driver_secrets`, with `{ store, ref, version }` leaves. A path cannot be in both. Referencing a secret the definition did not write needs a secret-use grant.
- `driver_secrets` (Dynamic, Sensitive) Secret inputs, an object of strings nested like the driver expects, such as `{ variables = { password = var.db_password } }`. A literal value is written to the built-in store; a whole placeholder such as `$${resources.db.outputs.password}` stays a template. The server never returns written values; `written_secret_refs` records the versions written, and a version changed outside OpenTofu plans a write of the value again.
- `name` (String) The display name, 1 to 100 characters without surrounding spaces. Defaults to the ID when the object is created.
- `provision` (Dynamic) Co-provisioned resources, an object keyed by `TYPE[.CLASS][#ID]` with `is_dependent`, `match_dependents` and `params`.

### Read-Only

- `written_secret_refs` (Dynamic) Where each literal value of `driver_secrets` was written, nested like it.
