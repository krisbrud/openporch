# openporch_resource_type (Resource)

A custom resource type, such as `acme/feature-flags`. Workloads request it and resource definitions provision it like a built-in type. Changes replace the type's body in place; deployments already accepted keep checking outputs against the schemas they recorded. Built-in types cannot be managed. A type that resource definitions use cannot be deleted, and deleting a type deletes its classes. Import it by ID.

## Example Usage

```terraform
resource "openporch_resource_type" "feature_flags" {
  id       = "acme/feature-flags"
  name     = "Feature flags"
  use      = "direct"
  category = "config"
  inputs_schema = {
    type       = "object"
    properties = { project = { type = "string" } }
  }
  outputs_schema = {
    type = "object"
    properties = {
      values  = { type = "object", properties = { url = { type = "string" } } }
      secrets = { type = "object", properties = { sdk_key = { type = "string" } } }
    }
  }
}
```

## Schema

### Required

- `id` (String) The type ID, `<org>/<name>`. Changing it replaces the type.
- `use` (String) How the type is used: `direct` (workloads request it), `indirect` (only other resources reference it) or `implicit` (one per environment).

### Optional

- `category` (String) A grouping for display, such as `datastore`.
- `inputs_schema` (Dynamic) JSON Schema of the resource inputs (a workload's `params`), an object. Left out, any object is accepted.
- `name` (String) The display name. Left out, a new type is named after its ID, and an existing or imported one keeps the name it has.
- `outputs_schema` (Dynamic) JSON Schema of the outputs: an object whose `properties` are the `values` and `secrets` schemas. Drivers' outputs are checked against it. Left out, any values and secrets are accepted.
